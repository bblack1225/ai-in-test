ai-in-test ・ 交付說明

手機 App 自動化測試工具：從 clone 到跑第一份測案

給接手的團隊看的安裝與使用說明。照第 1 到第 7 步做完，就能在網頁上看到你們 App 的畫面地圖、用 LLM 產生測案，並在手機上執行。之後每次使用只要一個指令。

這套工具做什麼

這是一套不用手寫 selector 的手機 App UI 自動化測試工具。它會掃描 App 畫面上的每個元件，用 LLM 幫沒有 id 的元件寫上用途說明，整理成一張「畫面地圖」。測案只要寫「在哪個畫面點哪個元件」，執行時工具會依序用原生 id、自動產生的 XPath、鄰近文字、座標去找到元件。

平常的操作都在一個本機網頁裡完成：

地圖檢視
看畫面地圖，從手機掃描補上新畫面
→ 地圖
測試情境產生
讓 LLM 從畫面推想值得測的情境
→ 情境清單
測案編輯
用對話產生或修改測案，存進專案
→ 測案
測案執行
在手機上跑單份或整批測案
→ PASS／FAIL

支援 iOS 實機和 Android 模擬器／實機，兩個平台共用同一套程式。電腦可以用 macOS 或 Windows，但能測的平台不同：

你的電腦能測的平台要做的步驟
macOSiOS Android1～4、5A 和／或 5B、6、7
WindowsAndroid1～4、5B、6、7。iOS 一定要用 Mac，因為建置和簽署都需要只有 macOS 版的 Xcode

下面每個指令如果兩個系統寫法不同，會分開標示 macOS 和 Windows。Windows 的指令都在 PowerShell 裡執行。

01取得程式

macOS 打開「終端機」，Windows 打開「PowerShell」，切到你想放程式的資料夾，然後 clone。電腦上還沒有 git 的話，先照第 2 步的表格裝好 git。

git clone https://github.com/bblack1225/ai-in-test.git
cd ai-in-test

之後所有指令都要在 ai-in-test 這個資料夾裡執行，程式會用相對路徑讀寫檔案。

02安裝共用工具

每一項都先用「確認指令」看看是不是已經裝過。macOS 用 Homebrew 安裝，還沒裝的話先照它首頁的指令安裝；Windows 用內建的 winget。

工具用途確認指令macOS 安裝Windows 安裝
git取得程式git --versionxcode-select --installwinget install --id Git.Git -e
uv管理 Python 版本和套件uv --versionbrew install uvwinget install --id astral-sh.uv -e
Node.js執行 Appiumnode --versionbrew install nodewinget install --id OpenJS.NodeJS.LTS -e
Appium 3手機自動化伺服器appium --versionnpm install -g appium（兩個系統一樣）

Windows 裝完之後要關掉 PowerShell 再重開，新裝的指令才找得到。各平台的 Appium driver 和開發工具（Xcode、Android Studio）在第 5 步裝。

不要直接用電腦上原本的 Python

這個專案需要 Python 3.12。macOS 內建的是 3.9，Windows 可能沒裝或是別的版本，直接用會出錯。之後執行程式一律用 uv run python ...，uv 會自動下載並使用專案指定的版本。

03建立 Python 環境

uv sync

uv 會自動下載 Python 3.12（不會動到電腦上原本的 Python），並在專案裡的 .venv/ 裝好所有套件，版本照 uv.lock 完全鎖定，每個人裝到的都一樣。確認：

uv run python -c "import appium, selenium, PIL, google.genai; print('套件 OK')"

不需要另外啟用虛擬環境。要加套件的話用 uv add 套件名，不要用 pip install，不然別人拿到專案時裝不到。

04建立設定檔

從範本複製一份自己的設定檔（PowerShell 也認得 cp，兩個系統一樣）：

cp config.example.toml config.toml

打開 config.toml，先在 [llm] 填入交付窗口給你的 API key：

[llm]
api_key = "交付窗口給你的 key"

裝置相關的欄位（[ios] 或 [android]）在第 5 步查到資料後再填。確認 key 讀得到（不會印出 key 本身）：

uv run python -c "import test_config as t; t.get_llm_client(); print('設定 OK，模型：', t.LLM_MODEL)"

config.toml 已經列在 .gitignore，不會被 commit。它含有 API key，不要傳給別人，也不要放進任何交付包。不想把 key 寫進檔案的話，也可以改設環境變數 GEMINI_API_KEY，兩個都有時以環境變數為準。

待測 App 的 bundle id／package 不填在這裡，填在專案設定（第 7 步），換測不同 App 時不用改這個檔案。

05AiOS 裝置設定 iOS 僅限 macOS

這一段的指令都只能在 Mac 上執行。用 Windows，或只測 Android 的話，跳到 5B。

安裝 Xcode 和 iOS driver

  1. 從 App Store 安裝 Xcode，打開一次讓它裝完元件，然後同意授權： 
    sudo xcodebuild -license accept
  2. 安裝 Appium 的 iOS driver： 
    appium driver install xcuitest

準備 iPhone

  1. USB 接上 Mac、解鎖，手機上點「信任這台電腦」。
  2. 開啟開發者模式：設定 → 隱私權與安全性 → 開發者模式。找不到這個選項，通常是手機還沒被 Xcode 連過，先做完下一段「簽署 WebDriverAgent」的步驟 3 再回來開。
  3. 查手機的 UDID，在 == Devices == 底下手機那一行，最後括號裡的值： 
    xcrun xctrace list devices
  4. 查待測 App 的 bundle id（第 7 步建立專案時要用）： 
    xcrun devicectl device info apps --device 你的UDID

簽署 WebDriverAgent

WebDriverAgent（WDA）是 Appium 裝到 iPhone 上、實際操作畫面的程式。手機桌面上會多一支 WebDriverAgentRunner-Runner，這是正常的，不要刪。

  1. Xcode 登入 Apple ID：Xcode → Settings → Accounts → 左下角 ＋ → Apple ID。沒登入的話，之後連線會報 xcodebuild failed with code 65。
  2. 打開 WDA 專案： 
    open ~/.appium/node_modules/appium-xcuitest-driver/node_modules/appium-webdriveragent/WebDriverAgent.xcodeproj
    TARGETS 選 WebDriverAgentRunner → Signing & Capabilities：勾選 Automatically manage signing，Team 選你的帳號，Bundle Identifier 自己取一個並固定使用，例如 com.你的名字.WebDriverAgentRunner。
  3. 上方 Scheme 選 WebDriverAgentRunner、裝置選你的 iPhone，按 Product → Test（⌘U）。手機跳出「不受信任的開發者」的話，到 設定 → 一般 → VPN 與裝置管理 → 信任，再按一次 ⌘U。手機出現 Automation Running 就成功了，按 ⌘. 停止。
  4. 查 Team ID。Xcode 的 Accounts 頁面只看得到團隊名稱，用終端機查，organizationalUnitName 那一行就是： 
    security find-certificate -a -c "Apple Development" -p | openssl x509 -noout -subject -nameopt multiline
免費 Apple ID 的簽署只有 7 天效期

到期後連線會報 0xe8008011 或 WDA 打不開。刪掉手機上的 WebDriverAgentRunner-Runner 讓 Appium 重裝，或重做上面的步驟 3，不用改 bundle id。免費帳號每 7 天最多註冊 10 個新的 App ID，所以 WDA 的 bundle id 決定後不要一直換。加入公司付費開發者團隊的話，效期是 1 年。

05BAndroid 裝置設定 Android

這一段還沒照新流程完整實機驗證

Android 的程式比 iOS 早開發、相對成熟，但這份安裝流程是依照 iOS 跑通的版本整理的，Android 部分還沒有從頭照著做一次。遇到跟這裡寫的不一樣的地方，請回報給交付窗口。

安裝 Android Studio 和 Android driver

  1. 安裝 Android Studio，第一次開啟時照預設裝好 Android SDK。用模擬器的話，在 Device Manager 建一台。
  2. 設定三個環境變數：ANDROID_HOME（Android SDK 的位置）、JAVA_HOME（Appium 要用的 Java），以及把 adb 所在的 platform-tools 加進 PATH。下面用的是 Android Studio 預設的安裝位置，你改過安裝位置的話要跟著改。
    macOS（寫進 ~/.zshrc）
    echo 'export ANDROID_HOME="$HOME/Library/Android/sdk"' >> ~/.zshrc
echo 'export PATH="$ANDROID_HOME/platform-tools:$PATH"' >> ~/.zshrc
echo 'export JAVA_HOME="/Applications/Android Studio.app/Contents/jbr/Contents/Home"' >> ~/.zshrc
source ~/.zshrc
    Windows（PowerShell）
    setx ANDROID_HOME "$env:LOCALAPPDATA\Android\Sdk"
setx JAVA_HOME "C:\Program Files\Android\Android Studio\jbr"
    Windows 的 PATH 請用介面加，不要用 setx 改（太長會被截斷）：開始選單搜尋「編輯您帳戶的環境變數」→ 使用者變數的 Path → 編輯 → 新增 %ANDROID_HOME%\platform-tools。
    設定完關掉終端機再重開，確認 adb version 有印出版本。
  3. 安裝 Appium 的 Android driver： 
    appium driver install uiautomator2

準備裝置和待測 App

  • 實機：開啟開發人員選項和 USB 偵錯，接上電腦後在手機上允許偵錯。
  • 模擬器（Android Studio 或 BlueStacks）：Appium 不會幫你裝待測 App，要自己先裝 APK。把 APK 拖進模擬器視窗，或執行 adb install 檔案.apk。
    • Apple Silicon 的 Mac 上模擬器是 arm64，APK 要支援 arm64-v8a 或是 universal 版本
    • 拿到 .aab 不能直接安裝，直接跟開發團隊要 APK 最省事
    • 金融類 App 常會偵測並擋掉模擬器，被擋的話改用實機
  • BlueStacks：它不會自動被 adb 看到，要先手動連線。這套工具還沒有在 BlueStacks 上實測過。
    1. BlueStacks 設定 → 進階 → 打開「Android 偵錯橋（ADB）」。旁邊會顯示連線位址，通常是 127.0.0.1:5555；同時開好幾個 BlueStacks 時，每個的 port 不一樣。
    2. 用 adb 連過去，port 換成畫面上顯示的那個： 
      adb connect 127.0.0.1:5555
    3. 每次重開 BlueStacks 後都要再連一次，工具不會自動幫你連。
  • 查裝置代號和待測 App 的 package（第 7 步建立專案時要用）。先在手機上打開待測 App，再執行（兩個系統一樣）： 
    adb devices
adb shell "dumpsys window | grep mCurrentFocus"
    第二行輸出裡 / 前面那一段就是 package。

06檢查環境

工具附了一個檢查指令，會逐項確認 Python 套件、config.toml、API key、Appium 和 driver、Xcode 簽署憑證、手機有沒有接上、adb、專案、網頁要用的 port。它只讀取資訊，不會操作手機。

uv run python aitest.py doctor --platform ios

測 Android 就把 ios 換成 android，兩個都用就拿掉 --platform。Windows 一定要加 --platform android，不然 iOS 那一段會因為沒有 Xcode 而失敗。每一項失敗都會寫怎麼修；照著修完再跑一次，直到沒有失敗項目。

「還沒有專案」這一項在第 7 步之前出現是正常的。WDA 簽署有沒有過期，doctor 看不出來；連線時報 code 65 或 0xe8008011 再照 5A 重簽。

07準備專案

一支 App 的一個平台是一個「專案」，例如 xxx-ios 和 xxx-android 是兩個專案，因為兩個平台的畫面結構不同，地圖不能共用。專案資料放在 workspace/projects/<專案代號>/，這個資料夾不進 git。

A. 匯入交付的專案 zip

拿到交付窗口給的 zip 時，用這個方式。

  1. 先只開網頁，不接手機： 
    uv run python aitest.py start --no-appium
    瀏覽器會自動打開 http://127.0.0.1:8767/。
  2. 頁首按「📂 匯入專案 zip」，選拿到的 zip。匯入完成後會自動開啟這個專案。
  3. 回到終端機按 Ctrl+C 關掉，接著照「每次使用」帶專案代號重新啟動。專案代號可以這樣查： 
    uv run python workspace.py list

B. 從頭建立專案

沒有現成資料，或要測一支新的 App 時，用這個方式。執行下面的指令，它會一步一步問專案代號、平台、顯示名稱、bundle id／package，最後確認才建立：

uv run python workspace.py create

bundle id／package 要填第 5 步查到的值，不確定可以先空白，之後再用 workspace.py update <專案代號> --bundle_id 查到的值 補。它決定工具要打開、檢查、重開哪一支 App，填錯的話連線會失敗。

建好之後地圖是空的，有兩種方式補上畫面：

  • 在網頁上手動建：在地圖檢視的節點詳情按「🌱 從這裡點出新畫面…」，工具會實際點擊手機，掃描新畫面加進地圖。
  • 用自動爬蟲：先關掉網頁伺服器、自己開 Appium（appium --address 127.0.0.1），手機停在要開始爬的畫面，例如 App 首頁。--root_name 是這個起始畫面在地圖上的名稱。第一次用很小的範圍試： 
    uv run python crawl_app_tree.py --project <專案代號> --map main --root_name 首頁 --max_depth 1 --max_screens 5 --safe_keywords
爬蟲預設會點擊所有元件

「下單、送出、確認」這類高風險按鈕，要加 --safe_keywords 才會跳過。連到正式環境或真實帳號時一定要加，也可以先加 --dry_run 看它打算點哪些。對同一張地圖重爬會整張蓋掉（蓋掉前會備份到 backups/），依功能分開爬時換 --map 名稱，例如 --map trading。

每次使用

  1. 手機接上、解鎖，打開待測 App。
  2. 帶專案代號啟動，平台會照專案設定： 
    uv run python aitest.py start <專案代號>
    它會在需要時自動啟動 Appium（只允許本機連線），接著啟動網頁伺服器並打開瀏覽器。
  3. 這個終端機視窗要一直開著。用完按 Ctrl+C，會一起關掉這次自動啟動的 Appium。
常用選項作用
--no-appium不接手機，只看地圖、編輯測案
--no-browser不自動打開瀏覽器
--port 87688767 被佔用時換一個 port
  • 網頁一定要從 http://127.0.0.1:8767/ 開。直接雙擊 HTML 檔的話，截圖顯示不出來，也連不到伺服器。
  • 沒帶專案代號時，平台預設是 iOS。開 Android 專案時如果看到「專案是 Android，但 viewer_server 目前接的是 iOS」，就是忘了帶專案代號：按 Ctrl+C 重開即可。
  • Windows 上按 Ctrl+C 結束後，下次連線如果失敗，關掉所有 Appium 視窗再重開一次通常就好了。
  • 網頁伺服器開著時會一直佔用手機連線，這時不要另外跑 crawl_app_tree.py、capture_screen_map.py 這類直接連手機的程式。要跑的話先按 Ctrl+C 關掉，再自己開 Appium：appium --address 127.0.0.1。

網頁四個分頁

地圖只從「地圖檢視」進來，其他分頁都用地圖檢視目前開著的那張；測案只從「測案編輯」進來，「測案執行」只負責選測案和執行。

地圖檢視

  • 頁首選「專案」和「地圖」。一個專案可以有好幾張地圖，通常依功能分開，例如交易、帳務各一張。「⚙ 管理地圖」可以新增、改名、複製、刪除。
  • 點節點看畫面細節和元件清單；點截圖可以在圖上直接選元件。
  • 改了會自動存檔到目前這張地圖，頁首會顯示存檔狀態。

測試情境產生

勾選畫面後按「分析並產生情境列表」，LLM 會列出值得測的情境。每個情境旁的按鈕會把它帶到「測案編輯」，開一份新測案。

測案編輯

  1. 選測案：「＋ 新測案」「📁 開啟專案測案」或「📂 匯入測案 JSON」。下方會顯示目前這份存了沒。
  2. 用 LLM 產生或修改：勾選相關畫面，用自然語言描述要測的流程，例如「在自選庫存點第一支股票，確認能進到個股總覽頁」。可以附上流程圖或規格書。
  3. 檢查和存檔：需要的話手動編輯 JSON，再「💾 存到專案」，或「➡ 送去執行」直接試跑。

換一份測案時會清掉之前的對話；目前這份有修改還沒存的話，會先問你。

測案執行

  • 單份執行：選一份專案測案（或測案編輯送過來的那份），按「▶ 執行測試」。建議勾選「執行前先檢查手機是否停在第一步的畫面」。
  • 批次執行：要先開專案。每一組選一張地圖，加入要依序執行的測案；重開 App 後需要登入的話，指定該組的「登入測案」。每份測案開始前，工具會自動回到它的起始畫面。整份批次可以「💾 存到專案」，下次直接開啟。

截圖和元件文字可能有帳號、金額等資訊。zip 只在團隊內部傳遞，不要 commit 進 repo，也不要給其他 App 的團隊。被取代的地圖都會先備份到專案的 backups/。

更新工具

工具由交付窗口統一維護，所有團隊共用。有新版時：

git pull
uv sync

你們的 workspace/ 和 config.toml 不在 git 裡，更新不會動到它們。請不要為了單一 App 直接改工具程式；遇到問題或需要新功能，回報給交付窗口，修好後所有團隊都會一起受益。

常見問題

症狀原因處理方式
TypeError: unsupported operand type(s) for |用到電腦上原本的舊版 Python改用 uv run python ...
剛裝好的 uv、appium、adb 找不到終端機是安裝前開的，還沒讀到新的 PATH關掉終端機（PowerShell）再重開
Windows 執行 appium 出現「因為這個系統上已停用指令碼執行」PowerShell 預設不允許執行 npm 裝的腳本改用 appium.cmd，或請 IT 依公司規範調整 PowerShell 執行原則
driver 明明有裝，卻出現 Could not find a driver for automationName ...同時開著好幾個 Appium，連到舊的那個macOS：lsof -nP -iTCP:4723 -sTCP:LISTEN，Windows：netstat -ano | findstr :4723，應該只有一個 PID。多的用 kill <PID>（Windows：taskkill /PID <PID> /F）關掉
iOS xcodebuild failed with code 65WDA 建置或簽署失敗，最常見是 Xcode 沒登入 Apple ID重做 5A「簽署 WebDriverAgent」步驟 1～3；要看詳細錯誤，在 config.toml 的 [capabilities.ios] 加 showXcodeLog = true
iOS 0xe8008011、WDA 打不開免費帳號的簽署 7 天到期刪掉手機上的 WebDriverAgentRunner-Runner，或在 Xcode 重按 ⌘U
Android doctor 說找不到 adbplatform-tools 沒加進 PATH照 5B 設定環境變數，開新的終端機再試
Android Appium 報找不到 ANDROID_HOME 或 JAVA_HOME環境變數沒設，或設了但終端機還沒重開照 5B 設定，重開終端機後用 aitest.py start 重新啟動 Appium
Android 裝置狀態是 unauthorized手機還沒允許這台電腦偵錯在手機跳出的視窗按允許
Android 用 BlueStacks，doctor 說看不到裝置BlueStacks 重開過，adb 的連線斷了再執行一次 adb connect 127.0.0.1:5555（port 照 BlueStacks 設定畫面）
Android 出現 adb server version ... doesn't match電腦上有兩份不同版本的 adb 在搶，常見於 BlueStacks 自己附的 adb 和 Android SDK 的 adb統一用 SDK 的 adb（5B 加進 PATH 的那個）。先關掉 BlueStacks，執行 adb kill-server，再重新連線
網頁警告「專案是 Android，但 viewer_server 目前接的是 iOS」啟動時沒帶專案代號，平台用了預設的 iOSCtrl+C 後用 aitest.py start <專案代號> 重開
port 8767 被佔用上一次的伺服器還開著，或有別的程式用了這個 port關掉另一個視窗的伺服器，或加 --port 8768。錯誤訊息會附上查是誰佔用的指令
操作沒反應、卡住手機鎖定，或自動化服務沒在執行手機保持解鎖；iOS 確認畫面上有 Automation Running，測試期間不要同時按兩顆音量鍵
LLM 功能出現找不到模型的錯誤設定的 Gemini 預覽版模型被 Google 下架在 config.toml 的 [llm] model_pro 換成當下的正式版

其他問題見 docs/TROUBLESHOOTING.md。

已知限制

  • 爬蟲在部分畫面回不去：原地切換內容、沒有真正返回鍵的畫面（例如分頁切換型的畫面），爬蟲失敗後自動復原可能點錯元件。遇到時改用手動建樹。
  • 重爬會蓋掉手動建的節點：對同一張地圖重爬是整張重建，手動加的節點要從 backups/ 補回，或把要爬的部分放到另一張地圖。
  • 捲動收集和截圖對不齊：手動建樹時勾選「同時捲動收集完整清單」，捲動後元件的框會跟截圖對不齊，所以這個選項預設不勾。
  • 一次只能有一個手機連線：網頁伺服器開著時，不要同時跑其他直接連手機的程式。
  • Android 爬蟲還沒有在實際 App 上跑過：只用真實畫面資料離線驗證過。
  • Windows 還沒有實機驗證：程式已經避開只有 macOS 才有的指令，但還沒有人在 Windows 上從頭跑過一次。遇到問題請回報給交付窗口。
