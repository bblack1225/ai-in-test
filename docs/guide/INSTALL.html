安裝步驟

照第 1 到第 6 步做完，最後 doctor 檢查沒有失敗項目就完成了。工具怎麼用請看使用說明。

還沒有 git 的話，先照第 2 步的表格裝。

03建立 Python 環境

uv sync

uv 會自動下載 Python 3.12，套件裝在專案的 .venv/。之後執行程式一律用 uv run python ...，不用啟用虛擬環境。

不能用 uv：改用 venv + pip

需要電腦上已經有 Python 3.12（最低 3.11，見下方「Python 版本」；macOS 內建的 3.9 不行），先用 python3 --version 或 python --version 確認。

macOS
python3 -m venv .venv
source .venv/bin/activate
Windows（PowerShell）
python -m venv .venv
.venv\Scripts\Activate.ps1

提示字元前面出現 (.venv) 就是啟用了。PowerShell 擋下 Activate.ps1 的話，先執行 Set-ExecutionPolicy -Scope Process -ExecutionPolicy Bypass（只對這個視窗有效）。接著安裝套件（兩個系統一樣）：

pip install "appium-python-client>=6.0.7" "google-genai>=2.25.0" "pillow>=12.3.0" "selenium>=4.49.0"

用這個方式的話，兩份文件裡的 uv run python 都換成 python。每次開新的終端機都要先啟用 .venv。

Python 版本：建議 3.12，最低 3.11

專案設定的、實際測過的都是 Python 3.12。程式本身最低需要 3.11（讀 config.toml 用的 tomllib 是 3.11 才有），3.10 以下跑不起來。

3.11 還沒有實際驗證過，套件版本也是照 3.12 鎖定的。能用 3.12 就用 3.12；用 3.11 遇到問題的話請改回 3.12。

04建立設定檔

cp config.example.toml config.toml

打開 config.toml，在 [llm] 填 API key：

[llm]
api_key = "交付窗口給你的 key"

config.toml 不會進 git，裡面有 key，不要傳給別人。也可以改用環境變數 GEMINI_API_KEY。[ios]／[android] 在第 5 步填。

05AAndroid 裝置設定 Android

這一步的重點是填 config.toml 的 [android]。Android Studio、adb、uiautomator2 driver 都裝好，裝置也已經能用 adb devices 看到的話，可以跳過下面的安裝和準備，直接填 config.toml。

安裝 Android Studio 和 driver

  1. 安裝 Android Studio，照預設裝好 Android SDK。用模擬器的話在 Device Manager 建一台。
  2. 設定 ANDROID_HOME、JAVA_HOME，並把 platform-tools 加進 PATH（以下是預設安裝位置）：
    macOS
    echo 'export ANDROID_HOME="$HOME/Library/Android/sdk"' >> ~/.zshrc
echo 'export PATH="$ANDROID_HOME/platform-tools:$PATH"' >> ~/.zshrc
echo 'export JAVA_HOME="/Applications/Android Studio.app/Contents/jbr/Contents/Home"' >> ~/.zshrc
source ~/.zshrc
    Windows（PowerShell）
    setx ANDROID_HOME "$env:LOCALAPPDATA\Android\Sdk"
setx JAVA_HOME "C:\Program Files\Android\Android Studio\jbr"
    Windows 的 PATH 用介面加（setx 會截斷）：搜尋「編輯您帳戶的環境變數」→ Path → 新增 %ANDROID_HOME%\platform-tools。重開終端機後 adb version 有版本就對了。
  3. 安裝 Android driver： 
    appium driver install uiautomator2

準備裝置

  • 實機：開啟開發人員選項和 USB 偵錯，接上後在手機上允許偵錯。
  • 模擬器：自己先裝好待測 APK（拖進視窗或 adb install 檔案.apk）。Apple Silicon Mac 要 arm64 或 universal 的 APK；金融 App 常擋模擬器，被擋就改用實機。
  • BlueStacks：設定 → 進階 → 打開「Android 偵錯橋（ADB）」，再用畫面上的位址連線。每次重開 BlueStacks 都要再連一次： 
    adb connect 127.0.0.1:5555

填 config.toml 的 [android]

udid 填 adb devices 看到的代號，例如 emulator-5554、127.0.0.1:5555（BlueStacks）或實機序號。

05BiOS 裝置設定 iOS 僅限 macOS

這一步的重點是填 config.toml 的 [ios]。Xcode、xcuitest driver 都裝好，iPhone 也已經簽署過 WebDriverAgent 的話，可以跳過下面的安裝和準備，直接填 config.toml（UDID、Team ID、WDA bundle id 不知道的話，查法在下面的步驟裡）。

安裝 Xcode 和 driver

  1. 從 App Store 安裝 Xcode，打開一次讓它裝完元件，再同意授權： 
    sudo xcodebuild -license accept
  2. 安裝 iOS driver： 
    appium driver install xcuitest

準備 iPhone

  1. USB 接上 Mac、解鎖，點「信任這台電腦」。
  2. 設定 → 隱私權與安全性 → 開啟開發者模式。沒有這個選項的話，先做完下面「簽署 WebDriverAgent」的步驟 3 再回來開。
  3. 查 UDID（== Devices == 底下手機那一行括號裡的值）： 
    xcrun xctrace list devices

簽署 WebDriverAgent

WebDriverAgent（WDA）是 Appium 裝到 iPhone 上操作畫面的程式，手機上會多一支 WebDriverAgentRunner-Runner，不要刪。

  1. Xcode → Settings → Accounts → ＋ 登入 Apple ID。
  2. 打開 WDA 專案： 
    open ~/.appium/node_modules/appium-xcuitest-driver/node_modules/appium-webdriveragent/WebDriverAgent.xcodeproj
    TARGETS 選 WebDriverAgentRunner → Signing & Capabilities：勾 Automatically manage signing、Team 選你的帳號、Bundle Identifier 取一個固定的，例如 com.你的名字.WebDriverAgentRunner。
  3. Scheme 選 WebDriverAgentRunner、裝置選你的 iPhone，按 ⌘U。手機出現「不受信任的開發者」就到 設定 → 一般 → VPN 與裝置管理 → 信任，再按一次 ⌘U。出現 Automation Running 就成功，按 ⌘. 停止。
  4. 查 Team ID（organizationalUnitName 那一行）： 
    security find-certificate -a -c "Apple Development" -p | openssl x509 -noout -subject -nameopt multiline

免費 Apple ID 簽署 7 天到期，到期後重做步驟 3 即可，bundle id 不要換。

填 config.toml 的 [ios]

欄位填什麼
udid手機 UDID
xcode_org_idTeam ID
wda_bundle_idWDA 的 Bundle Identifier
launch_bundle_id通常留空（直接操作前景的 App）

06檢查環境

macOS 測 iOS
uv run python aitest.py doctor --platform ios
測 Android（Windows 一定要加 --platform android）
uv run python aitest.py doctor --platform android
第 3 步用 venv + pip 安裝的話

先在 ai-in-test 資料夾啟用 .venv（提示字元前面出現 (.venv) 就是啟用了），再把上面指令的 uv run python 換成 python：

macOS 測 iOS
source .venv/bin/activate
python aitest.py doctor --platform ios
macOS 測 Android
source .venv/bin/activate
python aitest.py doctor --platform android
Windows（PowerShell）測 Android
.venv\Scripts\Activate.ps1
python aitest.py doctor --platform android

同一個終端機視窗啟用過一次就好，之後不用再打 activate 那一行；開新的視窗才要重新啟用。

每個 ❌ 下面都有修法，修完再跑，直到沒有 ❌。「還沒有專案」在這時出現是正常的，接著看使用說明的「準備專案」。

安裝常見問題

症狀處理方式
TypeError: unsupported operand type(s) for |用到舊版 Python。改用 uv run python ...，或確認 .venv 已啟用
剛裝的 uv、appium、adb 找不到關掉終端機再重開
Windows 執行 appium 或 Activate.ps1 出現「已停用指令碼執行」appium 改打 appium.cmd；啟用 venv 見第 3 步的 Set-ExecutionPolicy
iOS xcodebuild failed with code 65Xcode 沒登入 Apple ID 或簽署失敗，重做 5B「簽署 WebDriverAgent」步驟 1～3
iOS 0xe8008011、WDA 打不開簽署 7 天到期，在 Xcode 重按 ⌘U
Android 找不到 adb、ANDROID_HOME、JAVA_HOME照 5A 設環境變數，開新的終端機再試
Android 裝置是 unauthorized在手機跳出的視窗按允許
Android adb server version ... doesn't matchBlueStacks 附的 adb 跟 SDK 的搶。關掉 BlueStacks，adb kill-server 再重連
